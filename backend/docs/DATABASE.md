# Database

- Engine: PostgreSQL (via `DATABASE_URL`).
- Every domain model uses a UUID primary key (`apps.common.models.UUIDTimeStampedModel`)
  plus `created_at`/`updated_at`.
- Relational modeling is preferred throughout; `JSONField` is used only for
  genuinely flexible content (service capability blocks, AI provider
  config, automation step config), never as a substitute for real columns
  or foreign keys.
- Key constraints:
  - `Service.slug`, `Product.slug`, `Insight.slug`, `Job.slug`, `Industry.slug`,
    `Technology.slug` are unique.
  - `OrganizationMember` has a unique constraint on `(organization, user)`.
  - `AIProviderConfig` has a unique constraint on `(provider, model_name)`.
- Custom `User` model (`apps.accounts.User`) is configured as
  `AUTH_USER_MODEL` before any migrations are generated, per project rule.

## Generating and running migrations

This repository ships with app scaffolding (`apps/*/migrations/__init__.py`)
but **not** pre-generated migration files, because migrations must be
generated by Django's autodetector against an installed Django version --
they were not created blind in this environment. On first setup:

```bash
python manage.py makemigrations accounts common file_storage company \
  services products insights industries technology careers contact \
  newsletter organizations ai_platform automation audit
python manage.py migrate
```

(App labels come from each `apps/<name>/apps.py` `AppConfig.label`; the
`ai` app's label is `ai_platform` to avoid clashing with third-party
packages named `ai`.)
